Common Questions

  • Do I need to pay for Claude Code? Yes. Students need a Claude Code subscription at the Pro level ($20/month) for the duration of the course.
  • Am I allowed to use AI on this course? Yes — it's required. See the AI Use Policy below; the short version is that using Claude Code is expected on every project, but you must be able to explain, defend, and verify anything it produces.
  • Quizzes: We do not offer extensions or reopen closed quizzes because we release the answers. We drop your 5 lowest quiz scores and your 5 lowest lecture-activity scores to account for illness, technical difficulties, or other unforeseen circumstances.
  • Slip days: Each student has a bank of 5 slip days to use across P1–P4 (not the Final Project). Slip days waive the late deduction but never move the hard cutoff — see Late Policy below.
  • Manual Grading: Project grading is results-based (does your code pass the auto-grader / meet the rubric) combined with a review of your git commit history to confirm both partners meaningfully contributed.
  • Getting Help: Office hours and email. Office hours are the fastest way to get unstuck.
  • I missed lecture: Check the schedule page for that lecture's pre-class readings and in-class activity. Do the reading, attend office hours with questions, and complete the activity before the next lecture.

Course Description

The software engineering landscape is shifting rapidly, and this course is designed to ensure you're leading the charge. In AI-Assisted Software Development and Intelligent Applications, you will master the two most critical skills for the modern developer: using AI to supercharge your own productivity and engineering the next generation of AI-powered software. We will dive deep into full-stack development, showing you how to leverage AI tools across the entire software life cycle — from initial system design and rapid coding to automated testing and cloud deployment — while teaching you how to architect and integrate intelligent models directly into your own applications. By the end of the term, you won't just be a faster coder; you will be a high-level engineer capable of building complex, AI-native systems from the ground up.

Official Course Description: This course examines the dual role of artificial intelligence in modern software development: as a transformative tool for developer productivity and as a core architectural component of next-generation software. Students will master AI-assisted development workflows to optimize the entire software development life cycle, leveraging intelligent tools for requirements analysis, code generation, debugging, and automated testing. The course provides rigorous, hands-on experience in full-stack development, teaching students how to architect and integrate large language models (LLMs) and AI agents into scalable applications. By utilizing industry-standard tools for version control, CI/CD, and cloud deployment, students will gain a comprehensive understanding of building, managing, and maintaining AI-native software at every stage of its life cycle.

Course Learning Outcomes

By the end of the course, students should be able to:

  • Leverage AI-Assisted Tooling: Integrate AI-driven development tools (such as Claude Code or similar agents) to accelerate code generation, refactoring, and documentation throughout the software life cycle. Use AI agents to manage version control software, containerization, and deployment tools.
  • Architect Intelligent Systems: Design and implement full-stack applications that incorporate Large Language Models (LLMs) and AI agents as core functional components rather than simple external features.
  • Implement Advanced Retrieval Patterns: Build and optimize Retrieval-Augmented Generation (RAG) pipelines using vector databases to provide applications with domain-specific context and memory.
  • Manage the Full-Stack Life Cycle: Execute the end-to-end development of a software product — from initial system design and API integration to automated testing and cloud deployment.
  • Evaluate AI Quality & Security: Critically assess AI-generated code and model outputs for technical accuracy, security vulnerabilities, and ethical considerations (such as bias and "hallucinations").
  • Automate Software QA: Utilize AI to generate comprehensive unit tests, integration tests, and performance benchmarks to ensure the reliability of complex, non-deterministic applications.
  • Optimize AI Performance: Balance technical trade-offs regarding model selection, latency, API costs, and token usage to create production-ready, scalable software.

Grading Breakdown

Your overall grade is based on the following:

  • Quizzes: 8% (about 27 quizzes, one per lecture; the 5 lowest quiz scores are dropped)
  • Lecture Activities: part of In-Class Participation below (the 5 lowest lecture-activity scores are dropped)
  • Projects: 54% distributed as follows:
    • P1 — Frontend Side-Scroller Game: 8%
    • P2 — Full-Stack Quiz Game: 11%
    • P3 — RAG-Based Smart Q&A Application: 11%
    • P4 — AI-Powered Code Review Agent: 11%
    • Final Project — Full-Stack Smart Application: 13%
  • 3 Exams: 30% distributed as follows:
    • Midterm 1 (Unit 1 content): 10%
    • Midterm 2 (Unit 2 content): 10%
    • Final Exam (Unit 3 content): 10%
  • In-Class Participation: 8% (attendance and engagement; lecture activities are the primary graded signal)

Graded Component Details

Quizzes:
  • A short quiz during every lecture testing pre-class reading comprehension.
  • Out of 27 quizzes, your 5 lowest scores are dropped. This is meant to accommodate emergencies, technical difficulties, or other unforeseen circumstances.
  • Extensions are not given on quizzes because we release the answers when the quiz closes.
Lecture Activities:
  • Most lectures have a hands-on in-class activity building toward that unit's connected project arc.
  • Activities use a parallel practice codebase — never your project repo — so you can focus on the concept without project pressure.
  • Your 5 lowest lecture-activity scores are dropped.
Projects:
  • Projects primarily focus on your ability to design, build, and understand AI-assisted software.
  • Please see the course schedule for project due dates.
  • Teams:
    • P1–P4 are completed in instructor-assigned pairs.
    • The Final Project is completed in self-chosen teams of up to 4 students.
    • Both partners are expected to meaningfully contribute. We review GitLab commit history per partner as the primary signal; a lopsided commit history may result in a point deduction for the partner who did not meaningfully contribute.
  • Submission:
    • Each project is its own standalone GitLab repo. Clone, branch, implement, push, and open a merge request; the CI/CD pipeline auto-grades your main branch.
    • You may push and as many times as you like before the deadline, but the grading script will only run at designated times (e.g. right after the due date).
  • Late Policy — Slip Days:
    • Each student has a bank of 5 slip days for the semester, usable on P1–P4 only (not the Final Project).
    • While you have slip days remaining, using one waives the late deduction for that day.
    • Once your slip day bank is exhausted, each additional late day costs a 10 percentage point deduction.
    • Hard cutoff: no submission is accepted more than 2 days after the due date, for any project, regardless of slip days remaining. Slip days waive the deduction within that 2-day window — they do not extend the window itself.
    • The Final Project has no slip days and no exceptions to its due date.
  • Project Grading:
    • Grading combines automated unit tests (including hidden tests), LLM-graded rubric criteria, a review of AI logs, and a review of commit history for balanced partner contribution.
    • For each project there is a required meeting with TAs for them to question you about your codebase and for any adjustments to errors in the automated portion of the grading.
Exams:
  • Each exam covers primarily the content from its unit.
  • Exams are traditional written exams, closed-book, closed-laptop.
  • Please see the course schedule for exam dates. Locations: TBD.

AI Use Policy

This course takes the opposite stance from most CS courses: Claude Code is a required, expected tool on every project. You are not just permitted to use AI — you are expected to use it as your primary development driver, the same way you'd use a compiler or a debugger.

The line we care about isn't "did you use AI." It's: can you explain, defend, and verify what it produced? This is the whole point of the Elephant-Goldfish Model workflow taught starting in Lecture 4 — design docs written before any code, a "Goldfish test" where a fresh AI session with no context has to be able to understand your design from your documentation alone, and a "mean code review" where you direct AI to tear apart your own finished code looking for problems. These exist so you demonstrate real understanding of what gets built, not just submit whatever the model outputs first.

Acceptable: using Claude Code (or another AI tool) to design, implement, debug, test, and review your project code, provided you can explain how it works, why it was built that way, and what its limitations are if asked in office hours or during a code review.

NOT Acceptable: submitting AI-generated code you cannot explain, defend, or reproduce the reasoning behind; using AI on quizzes or written exams (which are closed-AI, closed-book); having a non-partner (human or AI acting on their behalf) do your share of a paired project's work.

Using AI in a way that violates this policy is academic dishonesty, even though AI usage itself is expected and required in this course.

How to Succeed in This Course

The best way to succeed in this course would be to:
  • attend in-person lectures with classroom engagement
  • complete the pre-class reading before each lecture — the quiz and activity both depend on it
  • treat AI-generated code as a first draft you must understand, not a final answer
  • start projects early; slip days run out fast across four projects
  • attend office hours when your auto-grader tests fail rather than guessing
